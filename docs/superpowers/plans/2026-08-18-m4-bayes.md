# telegram-antispam M4 — Naive Bayes + Sample Import — Implementation Plan

> **Status: ✅ Implemented, reviewed, and merged to `main`.** Every step below is complete; the whole-branch review passed. Checkboxes are ticked for historical record.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add a naive Bayes classifier over normalized tokens as the cascade's borderline stage — trained from idempotently-imported spam/ham samples and from admin feedback — so the bot catches spam that hard rules and behavioral checks miss, with `hard_hit OR bayes>=threshold` deciding the verdict.

**Architecture:** Bayes is a pure scorer in `internal/detect` operating over token counts it receives through a `BayesSource` interface (spec §3.1 keeps detection store-free). Token counts live in SQLite as feature frequencies — never raw ham text (spec §9 privacy). Import tokenizes samples and bumps per-(scope,token,label) counts, deduped by the sample's normalized hash so re-import never double-counts. The cascade gains a stage after behavioral: for non-trusted senders, if the Bayes spam-probability crosses the configured threshold, it's an actionable verdict. Admin "confirm spam" / "false positive" buttons feed the same counts.

**Tech Stack:** Go 1.24+, `modernc.org/sqlite`, stdlib (`math`, `crypto/sha256`). All build/test in Docker (`golang:1.26`) via `./scripts/dev.sh`.

**Spec:** `docs/superpowers/specs/2026-08-18-telegram-antispam-design.md` (implements build-order item 7 of spec §15).

## Global Constraints

- **Module path:** `github.com/stufently/telegram-antispam` (verbatim).
- **No host installs.** Every `go` command via `./scripts/dev.sh` in `golang:1.26`.
- **Detection stays pure (spec §3.1):** `internal/detect` imports only `domain` + stdlib. Bayes counts arrive via a `BayesSource` interface implemented by the store.
- **Privacy (spec §9):** store token *frequencies*, never raw ham message text. The `samples` table keeps only `(scope,label,origin,normalized_hash)` for dedup; token counts live in a separate features table.
- **Idempotent import (spec §9):** `(scope,label,normalized_hash)` is unique; importing the same sample twice must NOT change counts. `samples.origin ∈ (preset,user)` so a preset re-import never wipes user-learned data.
- **Verdict rule (spec §5):** `hard_hit OR bayes_score >= threshold`. Bayes runs only for non-trusted senders (trust skips the expensive semantic stage, spec §5.2), and only when no earlier hard/behavioral hit fired.
- **Bayes score is not a calibrated probability without calibration** (spec §4-review) — expose the raw log-ratio and a threshold; don't claim it's P(spam).
- **English only**; commit ≤50-char imperative, no trailers, one commit per task; TDD.

### Task 2: Bayes scorer (pure)

**Files:**
- Create: `internal/detect/bayes.go`
- Test: `internal/detect/bayes_test.go`

**Interfaces:**
- Produces:
  - `type BayesCounts struct { SpamDocs, HamDocs int; SpamTokenTotal, HamTokenTotal int }` — corpus totals.
  - `type BayesSource interface { TokenCounts(scope string, tokens []string) (spam map[string]int, ham map[string]int, err error); Totals(scope string) (BayesCounts, error) }` — the store provides counts for exactly the query tokens (avoids loading the whole model).
  - `func BayesLogRatio(src BayesSource, scope string, tokens []string, vocabGuess int) (float64, error)` — returns `log P(tokens|spam) + log P(spam) - (log P(tokens|ham) + log P(ham))` using Laplace(+1) smoothing over `SpamTokenTotal + vocabGuess` (and ham). Positive ⇒ spam-leaning. Returns 0 (neutral) when both corpora are empty.
  - `func BayesIsSpam(src BayesSource, scope string, tokens []string, vocabGuess int, threshold float64) (bool, float64, error)` — true when logRatio >= threshold.

### Task 4: Idempotent sample import

**Files:**
- Create: `internal/train/import.go`
- Test: `internal/train/import_test.go`

**Interfaces:**
- Consumes: `store.*DB` (`InsertSample`, `BumpBayes`), `detect.Normalize`/`Tokenize` — but `train` may import `detect` and `store` (it's an application package, not `detect`).
- Produces:
  - `func SampleHash(text string) string` — sha256 hex of the normalized text (`detect.Deobfuscate` applied), used as the dedup key. (This is a *sample* fingerprint, not a message identity.)
  - `func ImportSample(db *store.DB, scope, label, origin, text string) (added bool, err error)` — normalize+tokenize the text; compute hash; attempt `InsertSample(scope,label,origin,hash)` — if it was a NEW row (added), `BumpBayes(scope,label,tokens)` and return true; if the sample already existed (unique hash), do NOT bump, return false. This makes re-import idempotent.
  - `func ImportFile(db *store.DB, scope, label, origin, path string) (added, skipped int, err error)` — one sample per non-empty line.
  - `store.InsertSample` must report whether it inserted a NEW row (fresh) — if it currently returns only `error`, extend it to `(fresh bool, err error)` using `INSERT OR IGNORE` + RowsAffected (mirror `MarkUpdateSeen`). Update the M2 admin caller accordingly.

## Milestone 4 Definition of Done

- `make test` (and `-race` on `detect`, `store`) green; `make build`/`make vet` clean.
- A tokenizer turns normalized messages into deterministic features; naive Bayes scores them in log-space with Laplace smoothing over store-held per-(scope,token,label) counts.
- `tg-antispam import` idempotently loads spam.txt/ham.txt (same sample twice ⇒ no double count), origin preset|user preserved.
- The cascade runs Bayes for non-trusted senders after behavioral checks; `hard_hit OR bayes>=threshold` decides; trusted senders skip Bayes.
- Admin confirm-spam / false-positive train the model (best-effort), still RBAC-gated.
- A calibration `Evaluate` computes precision/recall on a holdout set.
- Nothing installed on host; all in `golang:1.26`.
