# JEV Integration Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Update the toolchain and dependencies, then add opt-in TypeSafe JEV classification.

**Architecture:** Implement the existing llm.Provider interface using the typed System One API. Reuse admission, borderline/always_for_untrusted selection, consensus, metrics and incident enforcement. No new detection bypass or veto.

**Tech Stack:** Go 1.27.3, standard net/http, existing YAML and Helm configuration.

**Spec:** User request and repository AGENTS.md; design decisions recorded here (user delegated decisions and execution).

## Global Constraints

- Preserve fail-open external classification and evidence-first sanctions.
- No live API credentials or message text in tests, errors or committed config.
- Default model jev-1.13.0, threshold 0.30 in (0,1], max_symbols 6000 in positive integers; explicit zero rejected.
- JEV uses a typed spam question with true/false criteria; per-call chat prompt replaces default instructions. Generative tuning parameters do not apply.
- JEV api_base is the complete endpoint; JEV_TOKEN overrides api_key.
- Stay on current branch as requested; commit and push task changes only.

## Review Focus

- Missing/null/wrong-type/out-of-range probabilities report errors, not successful ham.
- Timeout/cancellation and non-2xx responses cannot become spam or leak text/token.
- Unicode request bounds preserve complete characters.
- Zero and nonfinite thresholds cannot silently default.
- Helm secret wiring and runtime provider construction must work without OpenAI credentials.
