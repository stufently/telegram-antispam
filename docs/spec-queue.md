# Очередь вех

Спека следующей вехи пишется после приёмки предыдущей: базовый sha скоропортящийся.

## M1 — приветствие новичку (спека готова)

`docs/specs/welcome-m1.md`. Эфемерное приветствие опцией на чат, go-telegram/bot v1.27.0,
предохранитель публичного «эфемерного» сообщения.

## M2 — капча на входе (в очереди, после приёмки M1)

Решение владельца 24.09.2026: опцией на чат, по умолчанию выключено.

- Конфиг по образцу `welcome`: `captcha.enabled` + карта `captcha.chats`, `mode: button | join_request`,
  `timeout` (напр. 2m), `on_fail: kick | keep_muted`, исключения: админы, боты, уже проверенные
  (приветствованные/с доверием), CAS/LOLS-хит — сразу в штатный путь блоклиста.
- `mode: button`: при вступлении мут (`RestrictMember`), эфемерная кнопка «я не бот» (callback с
  проверкой, что нажал сам вступивший), нажал — `UnrestrictMember`, таймаут — `on_fail`. Эфемерное
  не гарантировано, поэтому нужен запасной путь: обычное сообщение с кнопкой, удаляемое после
  нажатия/таймаута (в дизайне §12: эфемерное не единственный путь проверки). Таймеры переживают
  рестарт — хранить дедлайны в SQLite.
- `mode: join_request` (только чаты со вступлением по заявке): `chat_join_request` в
  `allowed_updates`; в личку заявителю (`user_chat_id`, окно 5 минут) кнопка, нажал —
  `approveChatJoinRequest`, таймаут — `declineChatJoinRequest`. Оба метода в библиотеке есть.
- Join Request Queries (Bot API 10.1: `ChatJoinRequest.query_id`, `answerChatJoinRequestQuery`,
  `sendChatJoinRequestWebApp`, `User.supports_join_request_queries`) в go-telegram/bot v1.27.0 НЕ
  реализованы (нет ни метода, ни поля `query_id` в модели). Использовать их — только через upstream-PR
  в библиотеку либо собственный HTTP-вызов в `internal/telegram` с сырым разбором апдейта; в M2 не
  закладывать, решить отдельно, если вариант через личку не устроит.
- Не трогать `delete_mute`, кнопки разбора и `/spam`; капча — отдельный путь, не инцидент.
- Объём, вероятно, больше одной вехи: M2a (button) и M2b (join_request).
